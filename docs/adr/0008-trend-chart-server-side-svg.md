# ADR-0008：趨勢圖採 Server-side SVG（無 JS 依賴）

狀態：已接受（2026-08-01）

## 情境

M5 趨勢比較需要在靜態 HTML 報告中加入「評分／排名／評級隨時間趨勢圖」與「多日並排比較」。報告頁已 654KB（首頁）、archive 頁 ~53KB，且部署為 GitHub Pages 靜態檔。趨勢圖選用何種渲染方式，影響可測試性、頁面體積與瀏覽器相依。

## 選項評估

| 方案 | 優點 | 缺點 |
| :--- | :--- | :--- |
| **Server-side SVG**（採納） | 純函式輸出確定、可單元測試；無 JS／無外部套件；靜態檔離線可讀；與現有「單頁靜態」哲學一致 | 頁面原始碼略增（每個 sparkline 約 1KB） |
| Vanilla JS 客戶端繪圖 | 原始碼較小（嵌入資料 JSON + JS） | 難以測試；需瀏覽器執行；與月曆 widget 不同但月曆僅簡單互動 |
| 純 CSS 條狀圖 | 最輕量 | 資訊量低，難以呈現雙指標（分數 + 排名倒序）趨勢 |

## 決策

- 趨勢圖由 Python 在生成報告時直接產出**行內 SVG**（`trends.sparkline_svg`），嵌入靜態 HTML。
- 圖型為 polyline + 面積填充 + 首末／區間標籤；排名採倒序（值小在上方）。
- 多日比較表以 `<table>` 並排（每格＝當日排名，title 顯示當日初評分與評級），純靜態。
- 資料不足（< 2 個交易日）時輸出「累積中」文字提示，不產生圖表。

## 影響

- `trends.py` 提供純函式（`sparkline_svg`、`build_time_series`、`comparison_data`、`trend_stats`），全部可離線單元測試。
- 報告與趨勢頁無需任何 JavaScript 即可呈現趨勢。
- 頁面體積：index 約 +70KB（25 檔 × 個案 sparkline + 比較表），趨勢頁獨立存放，archive 頁維持精簡（不內嵌趨勢圖）。
