# ADR-0010：評分校準 — 分布準則 + 評級一致性覆寫

狀態：已接受（2026-08-01）

## 情境

2026-08-01 深度分析分布（25 檔）顯示品質問題：
- `value_score` 21/25 集中在 **80 分**（min 60, max 90）— LLM 錨定單一舒適值。
- 評級 **強力推薦 18／值得關注 6／中立觀望 1**（72% 強力推薦），無「暫時避開」。
- **供應商→評級系統性偏誤**：gemini 全給「值得關注」、cloudflare 多給「強力推薦」（`analysis.json.gz` 之 `provider` 欄位比對）。
- 初評分分布健康（==100 僅 1 檔、20–50 為主）→ **scoring.py 不需改動**。

## 決策

1. **`analyzer.py` SYSTEM_PROMPT 加分布準則**（JSON schema 不變，向後相容）：
   - value_score：60＝訊號分歧基準；常態 55–85；僅 ≥2 維度同時明確轉佳才 >88；明顯負面才 <40；避免一律相近分數。
   - 評級：強力推薦需 ≥2 維度轉佳且無顯著風險；訊號不明預設中立觀望；高分(>85)不得配暫時避開、低分(<55)不得配強力推薦；避免過度集中單一評級。
2. **評級採「LLM＋一致性覆寫」混合制**（`parse_deep_analysis`）：
   - 每個評級對應合理 value_score 帶：強力推薦[75,100]／值得關注[55,89]／中立觀望[40,74]／暫時避開[0,54]。
   - 分數→評級門檻：≥85 強力／≥70 值得／≥50 中立／<50 暫時避開。
   - LLM 評級落於帶外 → 覆寫為門檻評級並 `logger.warning`（記錄 舊→新）；評級空缺時由分數推導。
   - 保留 LLM 語意判斷，僅校正重大落差（避免 provider 偏誤放大為無意義評級）。
3. **供應商偏誤修正於 prompt 與 parse**，**不暴露給使用者**（見 Item 2 決策：公開報告不提模型）。

## 影響

- 現有合理組合（如 85＋值得關注）不受影響；帶外組合自動校正。
- 排程驗證：下一個 06:00 執行後比對 value_score 分布／評級多樣性／provider→評級。
